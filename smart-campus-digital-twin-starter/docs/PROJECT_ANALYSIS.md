# 参考项目拆解与复刻策略

## 1. 这个项目在表达什么

参考画面属于典型的园区级数字孪生运营大屏。它并不只是“三维地图加几个数字”，而是把空间对象、业务指标、运营状态、告警和交互导航绑定在同一套界面里。

宏观模式的中心是园区三维总览。楼宇、道路、绿化、停车场和周边城市体块形成空间语境。左侧 Board 主要承载能源与资源趋势，右侧 Board 主要承载电梯、设备和停车等设施运营状态。顶部负责系统标题、天气、时间和品牌；底部负责业务模块切换。三维场景中的停车点位、设备点位和楼宇标签属于空间化业务标注。

楼宇模式将关注范围从“整个园区”缩小到“单栋建筑”。参考画面中的建筑外壳被弱化或半透明，楼层和内部空间获得更高视觉权重，楼顶或楼层附近出现实时数据标签。此时宏观 Board 应替换成建筑环境、设备、楼层能耗、空间占用和告警面板，而不是继续显示园区总量。

## 2. 页面布局比例

```text
┌──────────────────────────── 顶部 8% ─────────────────────────────┐
│ 天气/位置             系统标题与装饰线              时间/品牌    │
├──────── 左侧 23% ────────┬──── 中央三维 54% ────┬── 右侧 23% ──┤
│ 能源总量                 │                       │ 电梯状态       │
│                          │  园区三维主体          │ 设备状态       │
│ 多组趋势曲线             │  标签、道路、点位      │ 停车状态       │
│                          │                       │ 环形仪表       │
├──────────────────────────┴───────────────────────┴────────────────┤
│                         底部导航 7%                               │
└──────────────────────────────────────────────────────────────────┘
```

中心三维区域并不是严格的 54% 宽度，因为左右 Board 使用半透明背景，视觉上会覆盖三维场景边缘。实现时应让 Canvas 铺满整个窗口，再把 Board 叠在上方，而不是把页面真实切成三列。这样道路、城市背景和光晕可以自然延伸到 Board 后面，画面会更完整。

## 3. 镜头与空间构图

宏观视角接近 35 至 45 度俯视的三分之四透视。它不是正交相机，但焦距偏长、透视压缩较明显，因此有“等距轴测图”的感觉。建议使用 35 至 45 度的透视视场角，并限制相机俯仰角和最小距离。

```text
                     Camera
                       ●
                      /|
                     / |
                    /  |
                   /   |
        ┌────────────────────────┐
        │   Campus bounding box   │
        │  楼宇集中在中心偏下      │
        │  道路形成外围引导线       │
        └────────────────────────┘
```

构图上的主要原则是：高楼分布在中心和两侧形成层次；前景保留道路和停车场；远景放置低对比度城市体块；主道路使用暖色，楼宇和数据使用冷色，从而在暗蓝背景里建立明确的颜色分工。

## 4. 可见光效与特效

参考画面的科技感主要来自多层效果叠加，而不是单个昂贵特效。

第一层是低照度环境与蓝色雾化。背景不是纯黑，而是深蓝黑，远景通过 Fog 逐渐融入背景。

第二层是楼宇边缘光。建筑主体很暗，屋顶轮廓、竖向边缘和窗格使用高亮青蓝色。WebGL 中可以通过 emissive 材质、Edges 或后处理 Outline 实现。

第三层是 Bloom。只有高亮发光材质应该越过 Bloom 阈值，普通墙体不应整体发白。代码中使用了高发光强度和 `toneMapped={false}` 的材质，让发光区域产生可控的辉光。

第四层是数据流。道路上的暖色光带、园区内部的青色流动虚线、楼宇之间的抛物线链路都在表达“能源、车辆或网络数据正在流动”。本 Starter 使用 Drei Line 的 dashed 材质和 dash offset 动画实现。

第五层是地面扫描。参考画面隐含了网格、扫描和雷达感。本 Starter 使用自定义 OpenGL Shading Language（GLSL）片元着色器绘制细网格、主网格、径向扫描环和轻微对角脉冲。

第六层是屏幕界面效果。半透明 Board、细线边框、切角、扫描线、暗角和微弱噪声共同制造“控制中心屏幕”的观感。它们大部分应使用 Cascading Style Sheets（CSS）实现，不必进入 WebGL。

## 5. 楼宇内部模式

真正的建筑内部可视化通常有三种表达方式。

```text
方案 A：整栋透明
┌─────────────┐
│ 透明外壳     │
│ 内部楼层可见 │
└─────────────┘

方案 B：剖切
┌──────────
│ 前立面被裁掉
│ 房间与设备暴露
└──────────

方案 C：爆炸分层
──── F06 ────
──── F05 ────
──── F04 ────
──── F03 ────
```

Starter 使用“透明外壳加轻微爆炸分层”，因为它不依赖真实建筑信息模型，也能清晰展示楼层选择。生产项目中可以进一步加入 Three.js clipping planes 实现动态剖切，或者将建筑信息模型预先拆成楼层和专业系统节点。

## 6. 复刻时的正确顺序

第一阶段先锁定画面构图。用简单 Box 建筑、基础道路和固定镜头复现中心构图，不要一开始做复杂模型。

第二阶段完成交互骨架。实现相机控制、楼宇拾取、宏观状态和楼宇状态切换。此时即使建筑仍是方盒，产品逻辑已经成立。

第三阶段搭建 Board 设计系统。统一颜色变量、边框、标题、数字字体、切角、面板间距和响应式策略。避免每个 Board 单独写一套样式。

第四阶段加入发光、Bloom、扫描网格、流线和雾化。每加入一层都检查对比度和帧率，不要一次堆满。

第五阶段接入真实资产和真实数据。只有当交互和视觉骨架稳定后，才开始处理 GLB、建筑信息模型、地理坐标、设备点位和接口。

第六阶段做性能治理。对树木、路灯、停车位和设备点位使用 Instancing；对远景使用 Level of Detail；对模型使用 Draco、Meshopt 和纹理压缩；对标签做聚合和视锥裁剪。
