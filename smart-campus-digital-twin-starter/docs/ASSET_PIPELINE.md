# 三维资产流水线

## 1. 坐标与单位

所有资产统一使用米作为单位，Y 轴向上，园区中心或项目测量原点作为局部原点。模型导出前应用缩放和旋转变换，避免运行时出现 `scale={0.001}`、绕轴补偿和巨大坐标值。

```text
推荐坐标
          +Y
           │
           │
           └──── +X
          /
        +Z
```

## 2. 模型层级

```text
Building_A
├── Shell
│   ├── Facade
│   ├── Glass
│   └── RoofGlow
├── Floors
│   ├── F01
│   ├── F02
│   └── ...
├── Rooms
└── Equipment
```

楼层剖析要求楼层是独立节点。动态隐藏专业系统要求暖通、电气、消防和给排水是独立节点。只做园区鸟瞰时可以把静态墙体合并，以减少 draw calls。

## 3. 材质与纹理

优先使用 Physically Based Rendering（PBR）工作流。单个园区项目应尽量建立共享材质库，避免每个网格复制一份相同材质。

颜色纹理使用 sRGB 色彩空间；法线、粗糙度、金属度和遮蔽纹理保持线性色彩空间。纹理尺寸应按屏幕实际占用选择，远景建筑通常不需要 4K 贴图。

建议把多个灰度通道打包到同一张纹理：

```text
R 通道 = Ambient Occlusion
G 通道 = Roughness
B 通道 = Metalness
```

## 4. 压缩

几何优先评估 Meshopt，兼容既有流水线时也可使用 Draco。纹理优先使用 KTX2 和 Basis Universal。压缩前先清理不可见面和微小构件，因为压缩不能替代几何治理。

## 5. 资产预算

| 资产级别 | 建议三角形 | 建议纹理 | 使用位置 |
|---|---:|---:|---|
| 园区远景楼宇 | 1,000–10,000 | 256–512 | 城市背景 |
| 园区主楼 | 10,000–80,000 | 512–2048 | 宏观主视角 |
| 单楼内部 | 100,000–500,000 分包 | 1024–2048 | 楼宇模式按需加载 |
| 设备模型 | 500–10,000 | 256–1024 | 近距离设备详情 |

预算应根据目标终端和并发可见对象调整。比单个模型三角形数量更重要的是同时可见 draw calls、材质切换和透明物体数量。

## 6. 加载策略

首屏只加载园区低精度资产。用户点击某栋楼后，再预取该楼高精度外壳和内部楼层。进入楼层后，再加载设备模型和房间详情。

```text
首屏
  └─ Campus LOD0
       └─ 点击 Building A
            ├─ 预取 Building A Shell
            └─ 预取 Building A Floors
                 └─ 选择 F05
                      └─ 加载 F05 Equipment
```
