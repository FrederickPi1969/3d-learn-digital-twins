# Exhibition Suite 4.0: White Gallery, In-World OS, Motion Media and Asset Channels

## What changed

Version 4 replaces the previous dark exhibition ambience with a high-key white gallery. The physical rendering changes are not limited to a background color: floor reflectance, wall roughness, environment light, directional light, skylight transmission, track lighting, fog color, tone mapping, bloom threshold, contact-shadow color and the outer heads-up display theme are coordinated as one lighting design.

The visitor operating system is no longer presented as a detached browser overlay or a freestanding kiosk. `ExhibitionScreens.tsx` creates one architectural wall assembly at the north wall. The assembly consists of a white physical housing, dark metal bezel, emissive edge, black display substrate and a Drei `Html` surface at the same world transform. The navigation dashboard and `VirtualDesktop` are two states of that same 1366 × 768 surface.

```text
Three.js wall geometry
        │
        ├── white physical housing
        ├── metallic recessed bezel
        ├── emissive cyan edge
        ├── black display substrate
        └── Html transform surface
                │
                ├── navigation dashboard
                └── visitor OS desktop
```

`openOs()` changes application state and requests the close wall-camera preset. It does not mount a full-window overlay. `closeOs()` unmounts desktop windows and restores the map on the same wall surface.

## Animated media screens

`AnimatedMediaScreens.tsx` creates four world-space displays backed by local H.264 MP4 files. Each screen owns a managed `HTMLVideoElement` and `THREE.VideoTexture`. The lifecycle implementation retries muted autoplay after the next pointer interaction, pauses when the page becomes hidden, removes the source during cleanup and disposes the texture.

The screen system is controlled by `mediaScreensEnabled` and `mediaScreenBrightness` in `useExhibitionStore`. Controls are available from the bottom dock and from the virtual operating system Settings application. The default media files live under `public/media/exhibition/` and can be regenerated with:

```bash
npm run media:generate
```

## Digital asset catalog

The release includes eighteen local GLB models: two lightweight replaceable learning models and sixteen project-owned procedural demonstration assets. The latter are generated by `scripts/generate-curated-demo-assets.py` and described by `public/models/exhibition/curated-demo/manifest.json`.

```bash
npm run assets:generate
```

The data model records provider, source label, license and credit next to every imported exhibit. `ExhibitBooth.tsx` normalizes arbitrary model bounds, moves the model onto its pedestal, optionally preserves source materials and applies a common environment response.

The provider registry recognizes bundled assets, Khronos glTF Sample Assets, Poly Haven, Smithsonian Open Access, downloadable Sketchfab records and a private Digital Asset Management repository. This list is an adapter boundary, not permission to redistribute arbitrary files. Every imported file must retain its record-level license.

The build-time synchronization utility accepts local or HTTP(S) GLB sources, validates the provider, rejects path traversal, enforces a 100-megabyte limit, verifies the binary glTF header, optionally verifies SHA-256 and writes a normalized manifest:

```bash
npm run assets:sync -- scripts/asset-manifest.example.json
```

Production credentials and vendor access tokens must remain in a server-side synchronization job. They must not be exposed through Vite environment variables.

## Main extension points

The physical room is in `src/components/exhibition/scene/ExhibitionHall.tsx`. Light fixtures are in `ExhibitionLighting.tsx`; post-processing is in `ExhibitionEffects.tsx`; the unified wall terminal is in `ExhibitionScreens.tsx`; dynamic media is in `AnimatedMediaScreens.tsx`; asset normalization and presentation are in `ExhibitBooth.tsx`.

The room is data driven. `src/data/exhibition.ts` maps 48 booth records to wall and floor coordinates. `src/data/exhibitionAssets.ts` is the local catalog and provider registry. Application and render controls are in `src/store/useExhibitionStore.ts`.

## Performance notes

Four simultaneous 960 × 540 videos are intentionally small and muted. When the media screen switch is off, the components unmount and release their textures and video elements. The 16 procedural GLB files are small enough for this starter, but production catalogs should remove blanket preloading, add distance-based loading, use KTX2 textures and apply Level of Detail to larger scans.

The embedded desktop is a Document Object Model surface transformed into the Three.js scene. It is visually and spatially integrated, but it is still a browser interface. Occlusion, very oblique camera angles and hundreds of simultaneous transformed HTML surfaces should be avoided. One large interactive wall surface is significantly more stable than dozens of small interactive HTML panels.
